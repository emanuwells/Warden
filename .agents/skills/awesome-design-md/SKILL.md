# Awesome DESIGN.md — wrapper WELLS

## Prioridade

1. Se o projeto já tiver `DESIGN.md` ou contrato visual WELLS, esse documento prevalece.
2. Só consultar uma referência externa quando o utilizador pedir estilo/inspiração ou não existir direção suficiente.
3. Selecionar uma única referência principal; misturar duas apenas com intenção explícita e regras claras.

## Processo

1. Escolher a referência mais próxima do contexto (produto, dashboard, marketing, editorial).
2. Extrair princípios, tokens, tipografia, spacing, estados e responsive behavior — não copiar identidade/asset proprietário.
3. Criar/adaptar um `DESIGN.md` do projeto usando `.agents/templates/DESIGN.template.md` quando a decisão for durável.
4. Implementar através de `frontend-design-direction`, Taste ou Impeccable conforme a superfície.
5. Verificar acessibilidade e adequação ao contexto institucional/empresarial.

O catálogo upstream é uma biblioteca on-demand; não deve ser vendorizado nem carregado integralmente no contexto.
